# Техплан: VoiceType — локальный голосовой ввод для Windows

*Рабочее название приложения: VoiceType. Версия плана 1.0. Документ предназначен для передачи локальному агенту (Claude Code или аналог).*

## 0. Инструкция агенту

- Работай строго по этапам из раздела 6. После каждого этапа проверь критерии приёмки и только потом иди дальше.
- Не добавляй функции вне раздела 10 (вне scope). Лучше меньше кода, чем больше.
- Все пути и версии зависимостей фиксируй в `requirements.txt` с точными версиями после первой успешной сборки.
- Если какое-то допущение из раздела 11 не подтверждается на практике, остановись и сообщи, а не выдумывай обходной путь молча.
- Коммиты маленькие, по одному на логическую задачу.

## 1. Цель

Десктопное приложение для Windows 10/11 x64. Пользователь зажимает глобальный хоткей, говорит (в том числе долго, несколько минут), отпускает хоткей, и распознанный текст вставляется в поле ввода активного окна, где стоит курсор.

Ключевые требования:

- Распознавание полностью локальное, через **faster-whisper** (CTranslate2). Интернет нужен только для обновления и докачки опциональных моделей.
- Работает на видеокарте NVIDIA с **2 ГБ VRAM** и на компьютерах вообще без GPU.
- Минималистичный современный интерфейс: иконка в трее, маленький оверлей-«пилюля» с визуализацией звука во время записи, окно настроек.
- Установщик `.exe` с выбором папки установки, кнопка «Проверить обновления» в приложении. Код на GitHub, сборка и релизы через GitHub Actions.

## 2. Выбранный стек и почему

| Задача | Решение | Обоснование |
| --- | --- | --- |
| Язык | Python 3.11 | faster-whisper существует только в Python, один язык на всё приложение, минимум склеивающего кода |
| Распознавание | faster-whisper | CUDA и CPU через один API, int8-квантизация |
| UI | PySide6 (Qt 6) | Нативный трей, прозрачные frameless-окна, кастомная отрисовка, тёмная/светлая тема. Только QtCore/QtGui/QtWidgets |
| Хоткеи | pynput (глобальный listener) | Нужны события нажатия и отпускания для push-to-talk |
| Запись звука | sounddevice (PortAudio) | Callback-стрим 16 кГц, моно, float32, без лишних зависимостей |
| Вставка текста | clipboard + эмуляция Ctrl+V через ctypes `SendInput` | Работает в подавляющем большинстве приложений, быстро при длинном тексте |
| Конфиг | JSON в `%APPDATA%\\VoiceType\\config.json` | Без лишних библиотек |
| Определение GPU | `ctranslate2.get_cuda_device_count()` + `nvidia-ml-py` (pynvml) для свободной VRAM | Нужна именно свободная память, а не общий объём |
| Сборка | PyInstaller в режиме `--onedir` | `--onefile` медленно стартует и чаще вызывает антивирусы |
| Установщик | Inno Setup 6 | Выбор папки, uninstall, тихая установка для обновлений |
| CI/CD | GitHub Actions на `windows-latest` | Сборка и публикация релиза по тегу `v*` |

Альтернативу (C# + whisper.cpp) не использовать: это другой движок, больше кода и нет faster-whisper.

## 3. Архитектура

Один процесс, четыре активных компонента.

- **Главный поток (Qt):** трей, оверлей, окно настроек, сигналы/слоты.
- **HotkeyListener (поток pynput):** ловит нажатие и отпускание заданной комбинации, шлёт Qt-сигналы `pressed` и `released`. Никакой тяжёлой работы внутри хука.
- **Recorder:** `sounddevice.InputStream` с callback. Пока хоткей зажат, складывает блоки в список. Параллельно считает RMS для визуализации и отправляет в оверлей (30 раз в секунду, не чаще).
- **TranscriptionWorker (QThread):** модель загружается один раз и живёт в памяти. По сигналу `released` берёт склеенный `numpy float32` массив, вызывает `model.transcribe`, собирает текст сегментов и отдаёт в `Inserter`.
- **Inserter:** сохраняет текущий текст из буфера обмена, кладёт распознанный текст, шлёт Ctrl+V, через 150–300 мс восстанавливает прежний буфер.

Поток данных:

```
hotkey down → Recorder.start → overlay: «слушаю» + волна
hotkey up   → Recorder.stop  → overlay: «обрабатываю»
            → Worker.transcribe(audio) → text
            → Inserter.paste(text) → overlay: скрыть
```

Состояния оверлея: `hidden`, `recording`, `processing`, `error`. Иконка в трее меняется в зависимости от состояния.

## 5. Профили моделей и выбор железа

Модели в формате CTranslate2 с Hugging Face:

- `Systran/faster-whisper-base`
- `Systran/faster-whisper-small`
- `Systran/faster-whisper-medium`
- `deepdml/faster-whisper-large-v3-turbo-ct2` (large-v3-turbo, быстрая и качественная, хороша для русского)

Автопрофиль при первом запуске (значения эмпирические, агент обязан откалибровать их скриптом `scripts/bench.py` на реальной машине пользователя):

| Условие | Устройство | Модель | compute\_type |
| --- | --- | --- | --- |
| NVIDIA, свободно ≥ 1.4 ГБ VRAM | cuda | large-v3-turbo | `int8_float16` |
| NVIDIA, свободно 0.8–1.4 ГБ | cuda | small | `int8_float16` |
| Нет NVIDIA или VRAM < 0.8 ГБ | cpu | small (≥ 6 физ. ядер) или base (меньше) | `int8` |

Правила:

- В настройках пользователь может вручную выбрать любую скачанную модель и устройство (`auto`, `cuda`, `cpu`).
- **Fallback:** если загрузка или inference на CUDA падает (OOM, нет DLL, старая карта), автоматически перезагрузить модель на CPU int8, показать уведомление в трее и записать причину в лог.
- Опция «выгружать модель из памяти после N минут простоя» (по умолчанию выключена), чтобы освобождать VRAM для игр и других задач.
- `cpu_threads` = число физических ядер.

Параметры `transcribe` по умолчанию:

```python
segments, info = model.transcribe(
    audio,                                  # np.float32, 16 kHz, mono
    language=cfg.language or None,          # "ru", "en" или None для авто
    task="transcribe",
    beam_size=5 if device == "cuda" else 1,
    vad_filter=True,
    vad_parameters=dict(min_silence_duration_ms=500),
    condition_on_previous_text=False,       # против зацикливаний на длинной речи
    initial_prompt=cfg.prompt or None,      # свой словарь терминов
    multilingual=cfg.language is None,      # для смеси русского и английского; нужна версия faster-whisper >= 1.1
)
text = " ".join(s.text.strip() for s in segments).strip()
```

Язык по умолчанию: русский. Переключатель в трее: Русский / English / Авто (смешанная речь).

## 6. Этапы разработки

### Этап 1. Ядро без UI (консольный прототип)

Задача: `python -m voicetype` слушает хоткей, пишет звук, распознаёт, вставляет текст.

- Реализовать `hardware.py`, `models.py`, `transcriber.py`, `recorder.py`, `hotkeys.py`, `inserter.py`.
- `scripts/bench.py`: прогнать модели на тестовом аудио 60 секунд, вывести время, RTF и пиковую VRAM.

Критерии приёмки:

- Зажал хоткей, сказал фразу, отпустил: текст появился в Блокноте и в поле ввода браузера.
- Запись 3 минуты распознаётся целиком без обрывов.
- На машине без CUDA (или при принудительном `device=cpu`) всё работает.
- Пиковая VRAM на выбранном GPU-профиле не превышает 2 ГБ.
- Случайное нажатие короче 0.3 с игнорируется.

### Этап 2. Интерфейс

- `tray.py`: иконка микрофона, меню (Настройки, Язык, Проверить обновления, Автозапуск, Выход). Иконка отражает состояние.
- `overlay.py`: пилюля 220×56 px у нижнего края экрана по центру (позиция настраивается), скруглённые углы, полупрозрачный фон, анимированная волна по RMS (около 24 столбиков) во время записи, плавное появление/исчезновение, спиннер при обработке. Тема подстраивается под системную.
- `settings.py`: хоткей (запись комбинации), язык, модель, устройство, микрофон, автозапуск, звуковой сигнал начала/конца, версия и кнопка «Проверить обновления».
- Оверлей **не должен забирать фокус** (см. раздел 8).

Критерии приёмки:

- Оверлей появляется при нажатии хоткея не позже чем через 100 мс.
- Курсор остаётся в поле ввода, фокус не теряется, текст вставляется куда надо.
- Окно настроек сохраняет и применяет параметры без перезапуска (кроме смены модели, которая перезагружает её в фоне).
- Второй запуск приложения не создаёт второй экземпляр.

### Этап 3. Упаковка

- `voicetype.spec` для PyInstaller `--onedir`, без консоли, с иконкой и version info.
- Исключить из сборки всё лишнее: torch, tkinter, QtWebEngine, QtQml, QtQuick и прочие модули Qt, кроме Core/Gui/Widgets.
- Включить данные пакетов: `collect_all("faster_whisper")` (там лежит модель VAD Silero), `collect_all("ctranslate2")`.
- Папка `models/small` (CTranslate2, скачана через `scripts/fetch_models.py`) копируется рядом с приложением. Приложение ищет модели в порядке: `{app}\\models`, затем `%LOCALAPPDATA%\\VoiceType\\models`.
- `installer/voicetype.iss` (Inno Setup 6):
  - фиксированный `AppId` (GUID) для корректных обновлений поверх;
  - диалог выбора папки установки (`DisableDirPage=no`);
  - `PrivilegesRequired=lowest` и `PrivilegesRequiredOverridesAllowed=dialog`, чтобы по умолчанию ставилось в профиль пользователя без UAC;
  - `AppMutex` (тот же, что создаёт приложение) и `CloseApplications=yes`, чтобы установщик закрывал запущенный экземпляр;
  - чекбоксы: ярлык на рабочем столе, автозапуск с Windows;
  - после установки опция «Запустить».

Критерии приёмки:

- Чистая Windows-машина без Python: установка, запуск, диктовка на CPU работают.
- Удаление через «Приложения и возможности» убирает программу, пользовательские модели и конфиг в `%APPDATA%` остаются (или спрашивается об их удалении).

### Этап 4. GPU-пакет

Библиотеки CUDA (cuBLAS 12 и cuDNN 9) весят 1+ ГБ, поэтому **не входят в основной установщик**.

- В CI собирается архив `voicetype-cuda-pack.zip` из pip-пакетов `nvidia-cublas-cu12` и `nvidia-cudnn-cu12` (только нужные DLL) и загружается как asset релиза (или отдельного релиза `cuda-pack-v1`, чтобы не пересобирать при каждом обновлении).
- При первом запуске, если обнаружена NVIDIA GPU и пакета нет, приложение показывает окно: «Найдена видеокарта. Скачать пакет ускорения (≈ N МБ)?» с прогрессом. Распаковка в `%LOCALAPPDATA%\\VoiceType\\cuda`.
- До импорта `ctranslate2` и `faster_whisper` добавить путь к DLL:

```python
import os
cuda_dir = os.path.join(user_data_dir, "cuda")
if os.path.isdir(cuda_dir):
    os.add_dll_directory(cuda_dir)
    os.environ["PATH"] = cuda_dir + os.pathsep + os.environ["PATH"]
```

- Без пакета приложение полностью работает на CPU.

Критерии приёмки: на машине с NVIDIA 2 ГБ после скачивания пакета модель грузится на CUDA, распознавание заметно быстрее CPU (зафиксировать RTF в README).

### Этап 5. Обновления

`updater.py`:

1. При старте (раз в сутки, в фоне) и по кнопке: `GET https://api.github.com/repos/OWNER/REPO/releases/latest`.
2. Сравнить `tag_name` с `__version__` (semver).
3. Если новее: показать «Доступна версия X.Y.Z», по согласию скачать asset `VoiceType-Setup-X.Y.Z.exe` с прогрессом.
4. Проверить SHA-256 (файл `SHA256SUMS.txt` в том же релизе).
5. Запустить `Setup.exe /SILENT /CLOSEAPPLICATIONS /RESTARTAPPLICATIONS` и завершить приложение.

Инсталлятор обновления **не содержит** CUDA-пакет и крупные модели (они лежат вне папки приложения и не затрагиваются). Модель `small` в установщике небольшая, поэтому обновление остаётся лёгким. Не использовать токены GitHub в коде: репозиторий публичный, API читается без авторизации.

Критерии приёмки: установить версию 0.1.0, выпустить 0.1.1, нажать «Проверить обновления» и получить обновлённое приложение в той же папке без повторного выбора пути.

### Этап 6. CI/CD

`.github/workflows/release.yml`, триггер: пуш тега `v*`.

1. checkout, `setup-python` 3.11, кэш pip.
2. `pip install -r requirements.txt pyinstaller`.
3. `python scripts/fetch_models.py` (скачать `small` из Hugging Face в `models/`).
4. `pyinstaller voicetype.spec`.
5. Установить Inno Setup (`choco install innosetup -y`), собрать `iscc installer\\voicetype.iss` с версией из тега.
6. Посчитать SHA-256, создать GitHub Release, приложить `VoiceType-Setup-X.Y.Z.exe` и `SHA256SUMS.txt`.

Лимит GitHub на один файл релиза: 2 ГБ. Основной установщик с `small` укладывается с запасом.

## 7. Крупные модели

Пользователь хочет иметь модели «в комплекте». Реализация:

- В основной установщик входит `small` (универсальная и достаточно качественная).
- Более крупные модели (`medium`, `large-v3-turbo`) докачиваются из настроек по кнопке «Скачать» с Hugging Face через `huggingface_hub.snapshot_download` в `%LOCALAPPDATA%\\VoiceType\\models`, с прогрессом и возможностью отмены.
- Опционально отдельная сборка `VoiceType-Setup-full-X.Y.Z.exe` с `large-v3-turbo` внутри, если итоговый размер меньше 2 ГБ. Делать только по явной просьбе пользователя.

## 8. Критические подводные камни (учесть обязательно)

**Оверлей не должен красть фокус.** Иначе Ctrl+V уйдёт в оверлей. После `show()` выставить расширенные стили окна:

```python
import ctypes
GWL_EXSTYLE = -20
WS_EX_TRANSPARENT = 0x20
WS_EX_TOOLWINDOW = 0x80
WS_EX_NOACTIVATE = 0x08000000
hwnd = int(widget.winId())
u32 = ctypes.windll.user32
ex = u32.GetWindowLongW(hwnd, GWL_EXSTYLE)
u32.SetWindowLongW(hwnd, GWL_EXSTYLE, ex | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TRANSPARENT)
```

Флаги Qt: `Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.Tool | Qt.WindowDoesNotAcceptFocus`, атрибут `WA_TranslucentBackground` и `WA_ShowWithoutActivating`.

**Вставка.** Перед Ctrl+V подождать отпускания модификаторов хоткея (иначе получится Ctrl+Alt+V и т.п.). Отправлять события через `SendInput`, восстанавливать буфер обмена с небольшой задержкой. Для окон с повышенными правами (запущены от администратора) вставка из обычного процесса не сработает: это ограничение Windows (UIPI), описать в README.

**Хоткей.** Комбинации с клавишей Win открывают меню «Пуск» и конфликтуют с системой. Дефолт: `Ctrl+Alt+Space` (настраиваемый). Хоткей должен работать в режиме «держать» и, опционально, в режиме «нажал — говорю, нажал ещё раз — стоп». Пока идёт обработка предыдущей фразы, новую запись принимать в очередь или блокировать с индикацией.

**Антивирусы.** Приложение с глобальным хуком клавиатуры и `--onedir` на PyInstaller иногда даёт ложные срабатывания. Использовать `--onedir`, не использовать UPX, добавить version info. В идеале подпись кода (вне scope v1, отметить в README).

**Hallucination на тишине и длинной речи.** `vad_filter=True`, `condition_on_previous_text=False`. Если итоговый текст пустой или распознана известная галлюцинация («Продолжение следует...», «Субтитры сделал DimaTorzok» и подобные), ничего не вставлять. Заложить небольшой список таких фраз в конфиг.

**Лимиты записи.** Максимум 10 минут за одну запись (настраивается). 16 кГц float32 это около 3.8 МБ в минуту, проблем с памятью нет.

**Микрофон.** Выбор устройства в настройках, обработка отключения устройства без падения приложения. При первом запуске проверить, что Windows разрешил доступ к микрофону для классических приложений, и если нет, показать понятную подсказку.

**Версии библиотек.** `ctranslate2` 4.x с CUDA 12 требует cuBLAS 12 и cuDNN 9. Зафиксировать совместимые версии `ctranslate2`, `faster-whisper`, `nvidia-cublas-cu12`, `nvidia-cudnn-cu12` и проверить сборку на чистой машине.

**Логи.** Файл `%LOCALAPPDATA%\\VoiceType\\logs\\app.log` с ротацией. В логе: выбранный профиль, устройство, причина fallback, время распознавания.

## 9. Нефункциональные требования

| Параметр | Цель |
| --- | --- |

## 10. Вне scope первой версии

- Потоковое распознавание в реальном времени (текст появляется во время речи).
- Перевод речи на другой язык.

## 11. Допущения, которые нужно подтвердить на железе пользователя

1. Видеокарта NVIDIA с поддержкой CUDA 12 (архитектура Pascal или новее). Агент проверяет это на этапе 1 и сообщает модель карты и свободную VRAM.
2. Профиль `large-v3-turbo` в `int8_float16` помещается в свободные \~1.4 ГБ VRAM вместе с рабочей памятью на длинных записях. Если нет, дефолтом на GPU становится `small`.
3. Основной язык диктовки: русский, с английскими вкраплениями (режим авто с `multilingual=True` проверить на реальных фразах).
4. Дефолтный хоткей `Ctrl+Alt+Space` устраивает пользователя (иначе заменить).
5. Репозиторий на GitHub публичный (нужно для обновлений без токена).
